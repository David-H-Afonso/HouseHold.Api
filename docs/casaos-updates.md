# CasaOS Compose Updates

Household reproduces CasaOS **Edit -> Update**, not the separate app-store `PATCH` update. For one fixed allowlisted app it fetches the current interpolated Compose YAML, writes a private backup, and sends those exact bytes back to CasaOS with:

- `GET /v2/app_management/compose/{id}` and `Accept: application/yaml`
- `PUT /v2/app_management/compose/{id}?dry_run=false&check_port_conflict=true`
- `Content-Type: application/yaml`
- `Authorization: <raw CasaOS JWT>` (no `Bearer` prefix)

The fetched YAML must contain `name: <appId>`. For CasaOS versions that omit the standard top-level name, Household also accepts the explicit top-level marker `x-household-compose-project: <appId>`; add that marker through CasaOS Edit before enabling Household updates for such a compose project.

## Setup

1. Persist `CASAOS_COMPOSE_BACKUP_ROOT` (default `/data/compose-backups`) on the same private `/data` volume as the database and Data Protection keys.
2. From an authenticated Household admin session, call `PUT /api/v1/admin/casaos/config` with:

   ```json
   { "internalBaseUrl": "http://casaos-host.example.lan", "rawToken": "<CasaOS JWT>" }
   ```

   Use a host/LAN URL reachable from the bridged container. Loopback, userinfo, query, and fragment components are rejected. The response never returns either value.

3. Call the app update endpoint with exact confirmation `UPDATE <appId>`. Allowed IDs are `household`, `doit`, `gamesdatabase`, `jellywatch`, `beastvault`, `warcraftarchive`, and `jellyfin`.

The token is encrypted with a purpose-specific ASP.NET Data Protection protector. Keep `/data/keys`, the SQLite database, and the backup root private and persistent. Rotating the CasaOS JWT means writing the new token through the same endpoint.

## Backups And Rollback

Backup identifiers are generated by the server. API responses expose IDs, never host filesystem paths. Rollback accepts an optional previous backup ID; omit it to select the newest valid backup. Before rollback, Household also fetches and backs up the current YAML.

CasaOS applies updates asynchronously. HTTP 202 from Household and status `Queued` mean only that CasaOS accepted the request. History is an acceptance/audit trail, not a live operation-progress feed. A rollback cannot restore application data, volumes, deleted registry images, or external dependencies. Confirm container state and application health in CasaOS after update or rollback.

App launcher responses expose nullable `updateAvailable`; malformed, oversized, redirected, non-JSON, or unavailable `/v2/app_management/apps/upgradable` responses produce `null`, never a false no-update claim. `adminActionsAvailable` is true only for an admin with valid server-side CasaOS configuration and an allowlisted app.

Do not mount `/var/run/docker.sock`, expose a generic CasaOS proxy, or place the raw CasaOS JWT in frontend/Vite configuration.
